Read `docs/SPEC.md` first. It is the full design.

## Current state (milestone 1: project skeleton)
- Builds and `runClient` works (without GraalJS, see below).
- Registered so far: 10 blocks (the Laptop is a block, since it is placed) and 3 standalone items as plain placeholders, plus one creative tab. Milestone 1 now builds and runs.

See `src/main/java/net/minecomputers/registry/`.
- Laptop GUI (`client/LaptopScreen.java`): layout and look from the approved mockup, now showing **real data**. Right-click on the placed Laptop: server (`network/NetworkScan.java`) flood-fills through Data Cables / Power Data Cables / the Brain (plain Power Cable carries no data), finds the Brain and devices touching the network, and sends a `LaptopSnapshot` packet; the client opens the screen from it. Not connected to a Brain = empty with a hint.
- `block/entity/BrainBlockEntity.java` stores the files (path -> content) and the device IDs (`servo:1` etc., assigned on first sight and kept) in the world save.
- **Files and editing work now:** `+ File` / `+ Folder` in the Explorer create inside the selected folder (click a folder row to select it; click empty space for the top level). The editor supports typing, arrows, Home/End/PageUp/PageDown, Tab (2 spaces), Enter with auto-indent, Backspace/Delete, click to place the cursor, mouse wheel, Ctrl+V. Saves automatically ~2 s after the last keystroke, on switching files, on closing, and with Ctrl+S. Client sends `LaptopAction` (create file/folder, save file) -> `network/ServerHandlers.java` validates (laptop exists, player within 8 blocks, laptop connected to the Brain, `PathRules`) -> Brain changes -> server answers with a fresh `LaptopSnapshot` (`open=false` so a late answer can never reopen a closed GUI).
- **Limit deviation:** max file size is 30000 bytes (`PathRules.MAX_FILE_BYTES`), not the spec's 64 KB, because vanilla caps a serverbound custom payload at 32767 bytes. Needs chunked upload to reach 64 KB. Total per Brain stays 512 KB, max 64 files and 64 folders.
- **Milestone 2 (first slice, written, not yet run):** GraalJS works in the dev client (fixed by depending on `org.graalvm.js:js-language` + `polyglot` instead of the POM-only `js-community`, whose .pom file was put on the game classpath). `script/BrainRuntime.java` = one isolated sandboxed GraalJS context per Brain (HostAccess.EXPLICIT, no class lookup, IOAccess.NONE, no threads/native/process/env/polyglot), `script/ScriptHost.java` = the only exported Java object, `script/ScriptManager.java` = all runtimes + per-tick global budget (15 ms) + shared Engine. Run/Stop/POLL are `LaptopAction`s; console goes back in `ConsoleSync` (versioned, only sent when changed; GUI polls twice a second). Runs `main.js` only (no import/require between files yet).
- **Script API now:** standard JS plus `console.log/info/warn/error` -> laptop Console panel; `get("screen:1")` (throws if the ID doesn't exist) returns `{ id, type }`, screens also get `.log(...)` (until Screen blocks exist, screen text shows in the Console panel tagged `screen:1`); `os.on("start", fn)`; `setTimeout/setInterval/clearTimeout/clearInterval` (50 ms = 1 tick, min 1 tick, max 64 timers).
- **CPU limits (deviation, to be tuned/moved into the config):** per call into the script 1,000,000 statements; wall-clock cap 250 ms for the first run of main.js and 25 ms per timer callback (the spec's ~2/5 ms is too tight for GraalJS in interpreter-only mode, there is no JIT here). Over the limit = script stopped + error in the Console. Max 100 console lines, 50 prints per call, 300 chars per line. Memory use of a script is NOT limited yet. Start is rate-limited to once per second per Brain. A Brain that is broken or whose chunk unloads stops its script. Scripts do not auto-start after a world reload yet.
- **Scripts stop themselves** when nothing is left to wait for (no timers), like Node: console shows "Script finished." and the status goes to Stopped. A `setInterval` script runs until Stop.
- **IDE polish (written, not yet run):** `LaptopScreen` now has multiple tabs (they share the bar width and shrink, then the bar scrolls with the mouse wheel; click = select, `x` or middle click = close, per-file cursor/scroll/undo kept), breadcrumb path bar, text selection (shift+arrows, mouse drag, double-click word, Ctrl+A), Ctrl+C/X/V (copy/cut with no selection = whole line), Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z undo/redo (per file, typing merged into steps), Ctrl+/ comment toggle, Tab/Shift+Tab indent/outdent, Ctrl+Left/Right word jump, smart Home, Ctrl+Home/End, Ctrl+W close tab, Ctrl+Tab / Ctrl+PageUp/PageDown switch tab, indent guides, scroll bars, Explorer and device list scroll with the wheel, window up to 620x350 GUI px.

## Gotchas learned earlier
1. GraalJS is `org.graalvm.polyglot:polyglot` + `org.graalvm.polyglot:js-community`, not the old `org.graalvm.js:js` group.
2. On NeoForge 1.21.8 and below a library must be in both `implementation` and `additionalRuntimeClasspath`, or it compiles but throws `NoClassDefFoundError` at runtime. Already done in `build.gradle.kts`.
3. GraalJS is not yet bundled into the mod jar. Jar-in-jar (so players don't need the library installed) is part of milestone 2.
